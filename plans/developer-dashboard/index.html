SESSION developer dashboard

in progress2026-10-03 · First release uses existing SESSION records. You can annotate this plan while implementation continues.

Goal

Give the developer a private /developer dashboard showing creator profiles, recent recorded activity, content and storage totals, room presence, and hosting health links. Only an explicitly selected verified account ID can access the page or API; ordinary members and guests receive no metrics or private user rows.

Non-goals

  • Account deletion, impersonation, private song/project contents, messages, credentials, and payments are outside this read-only overview.
  • Page views, visitors, retention, and error-rate history need additional instrumentation. Existing profile/action records will be labeled precisely; missing measurements will not be shown as zero.

Screens & flows

Uses SESSION's dark surfaces and red accents, with readable cards and a mobile user list.

Overview

Creator profiles, new profiles in seven days, recorded active creators, projects, community tracks/posts, media bytes, reports, and recent room presence. Fourteen UTC days of new profiles, explicit metric definitions, manual refresh, database reachability and Vercel logs links.

Creator directory

Search and paginate names/usernames with profile visibility, creation date, and project/track counts. No private content is opened. An owner-only link appears under SESSION's More navigation.

Risks

ACCESSEditable profile roles must never grant developer access. Bind only a verified authentication ID through server configuration, check every request before any query, return private/no-store responses, and clear data when access ends. Profile creation is not total auth registration; recorded actions are not page visits.
