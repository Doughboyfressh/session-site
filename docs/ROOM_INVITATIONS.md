# Invitations inside a studio session

The room host can choose **Invite people** beside **Copy invite**, search public SESSION members by name or `@username`, and send an invitation without leaving the active room or its Studio. The recipient receives an Alert with **Join session** and **Decline**. Joining opens the same room; camera and microphone stay off until the recipient explicitly joins the call. Existing copyable invitation links still work.

Invitations expire with the room's invite link. The dialog offers **Refresh invitations** after expiry; replacing invitations or removing a member invalidates pending invitations from the previous link. Invitations do not reserve a seat: acceptance enforces the four-person room limit. Duplicate sends create one alert. Declined invitations cannot be accepted. Only the named recipient can respond, only the host can send, and blocked connections and private directory profiles are excluded. Joining preserves the existing separate project editing permission.

The feature uses existing private notifications and room membership records, with no schema migration. Activity responses expose invitation status and expiry, never the bearer token or internal notification key. Account exports also omit internal notification keys. Alerts refresh every 15 seconds while open. Expired, replaced, closed, and full sessions show their state instead of silently granting access.

`node tests/backend-checks.mjs` executes the actual routes against SQLite, covering sending, deduplication, recipient authorization, join/decline, expiry, rotation/removal, blocked users, and a seat filled between authorization and insertion. Both deployment builds and the normal regression suites must pass.

For desktop/mobile interaction review, start `node node_modules/vite/bin/vite.js --config tests/vite.harness.config.mjs`, then open `http://127.0.0.1:4173/tests/room-invitations-harness.html`. The fixture uses the actual room, invitation dialog, and Activity components, with explicitly synthetic local responses. Switch between host and invitee to check sending, acceptance, decline, search, error handling, full sessions, and invitation refresh. This fixture sends no real notifications.

`tests/room-invitations-http-checks.mjs` checks the deployed Neon runtime using two disposable accounts, never real invite recipients. Set `SESSION_VERIFY_BASE` and load the matching private database environment with `node --env-file=.env.local tests/room-invitations-http-checks.mjs`. It verifies PostgreSQL search/status fields, delivery, deduplication, recipient authorization, join/decline, blocked/full/expired/closed sessions, and safe account export. Cleanup deletes only this run's room and actor records, verifies their absence, and records the two Auth user IDs under ignored `outputs/room-invites-evidence`; remove those exact users through Neon Auth admin after successful database cleanup.
